=============================================================================

on port 8098, before any verifier used these scripts. This directory is proof
that the app side of the tooling works end to end. It is NOT proof-run
evidence for any DoD row: the run below is synthetic, so it carries no
generation ids, no billed cost and no Langfuse session.

4. overhead-harness-check/ - measure_overhead.py, end to end
-----------------------------------------------------------------------------

  .venv/Scripts/python.exe scripts/observability/measure_overhead.py \
      --runs 1 --branch-delay 1 --port-on 8110 --port-off 8111 \
      --env LANGFUSE_BASE_URL=http://127.0.0.1:9 \
      --env LANGFUSE_HTTP_TIMEOUT_SECONDS=2 \
      --out docs/observability/evidence/tooling-smoke/overhead-harness-check

  ONE run per arm, not the three E4 requires: this is a harness check, not the
  E4 measurement. Both LANGFUSE_BASE_URL values point at a black-hole port so
  that nothing from a half-built exporter reached the shared Langfuse project.

  PROVED: both server arms start and answer /healthz, runs alternate on/off,
  both reach "completed", both processes are killed by PID, and the exporter's
  own summary line is found and parsed - enqueued/dropped/sent/http_errors and
  enqueue p50/p95 - with the OFF arm correctly reporting "not found".

  FOUND, and it is why the launcher is what it is: NOTHING in src/brief_crew/
  calls logging.basicConfig or dictConfig, and uvicorn configures handlers for
  the three `uvicorn*` loggers only. A `brief_crew.*` INFO record therefore
  reaches a root logger with no handler and is served by logging.lastResort,
  which emits WARNING and above - so under a bare `serve.exe` the exporter's
  INFO summary line is DROPPED, and the first run of this harness reported
  "not found" on both arms for that reason alone. The script now launches
  `python -c "logging.basicConfig(level=INFO); serve()"` instead, and the line
  appears. `--use-serve-exe` restores the old behaviour.

5. What this smoke test did NOT exercise
-----------------------------------------------------------------------------

  - The per-TASK duration table is empty here, and correctly so: the synthetic
    double emits agent-execution frames only (all 12 AGENT frames carry a
    `task` key), and no TaskStarted/TaskCompleted pair. Per-task TOKENS still
    populate, because the actor stamp puts `task_name` on every TOKEN frame.
  - No Langfuse session, no scores, no open-span check against real data, and
    no membership check between two concurrent runs.
  - No billed cost: nothing here was paid for.

  The Langfuse-side parsing was tested separately against the saved audit
  exports and against the one real session in the project; the OpenRouter side
  against two real generation records from the Task 1 probes. Those runs are
  not saved here because their subject is another worker's data, not this
  run's.
