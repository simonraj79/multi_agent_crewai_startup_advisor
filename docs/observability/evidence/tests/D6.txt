ends failed and not cancelled, the reason names the ceiling AND the figure, the
run span is ERROR, the run_status score says failed, and nothing is left
without an end time.

What was broken and is now fixed is the DISCRIMINATOR. _terminal_of treated any
cancelled frame carrying a non-empty reason as the budget stop, and
RunRegistry._fail_interrupted emits {"status": "cancelled", "reason":
"service_restart"} for a run orphaned by a process restart - so with
autoDeploy: yes on both Render services, every push to main could report an
interrupted run in Langfuse as a run that breached a $0.00 cost ceiling, a
fabricated money figure in the surface whose job is to be believed about money.

Current code (langfuse_exporter.py:1001-1055) compares against two named
constants and has a third branch for anything else:

  reason == COST_CEILING_REASON  -> failed, ERROR, the ceiling and the figure
  reason == INTERRUPTED_REASON   -> failed, ERROR, "interrupted by a service
                                    restart before the run finished" - and NO
                                    money figure, because there is none
  any other reason               -> still cancelled, WARNING, reason reported
  no reason                      -> cancelled, WARNING, "cancelled by operator"

Three of those four are now pinned by tests that did not exist in the first
pass (InterruptedRunTests, and OperatorCancelTests for the fourth), and
ReasonConstantMirrorTests asserts the two constants in mapping.py still equal
the registry's own - which is the mirror-drift failure mode this repository has
already paid for once with the builder's problem codes.
