2. THE CUSTOM TOOL - THE 401 AND THE 201
-----------------------------------------

  $ curl -sS -X POST $BASE/api/builder/tools/custom -H 'content-type: application/json' \
         --data '{"name":"sounding_line_lookup", ... }'
    -> HTTP 401
    {"detail":"sign in to use this endpoint"}

  $ ... the same, plus  -H 'X-Synthetic-User: proof-runner'
    -> HTTP 401
    {"detail":"sign in to use this endpoint"}
    (the header is IGNORED, not honoured: `synthetic_identity` needs
     `synthetic=True` AND an unset AUTH_BASE_URL, and this backend is neither)

  $ ... the same, plus  -H "Authorization: Bearer <TAMPERED>"
    -> HTTP 401
    www-authenticate: Bearer error="invalid_token"
    {"detail":"your session has expired; sign in again"}
    (one signature byte flipped by `mint_identity.py token --tamper`; header,
     payload, kid and expiry all untouched. This is what makes the 201 below
     evidence that the signature was CHECKED rather than merely present - the
     two 401s carry different WWW-Authenticate values, so the refusals are
     distinguishable: plain `Bearer` for nobody, `error="invalid_token"` for a
     bad one.)
