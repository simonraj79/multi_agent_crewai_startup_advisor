# The judge loop

This directory is where a feature is decided finished. A feature is done
when its critic can no longer land a hit, not when the builder says so.
Written 2026-09-02; nothing in it has run yet, and `DEFECTS.md` says so.

## Capture recipe

Ours is produced by `frontend/e2e/capture.spec.ts` (planned) against the
free backend, so every capture is reproducible and costs nothing:

```powershell
$env:SYNTHETIC = "1"; $env:SYNTHETIC_BRANCH_DELAY_SECONDS = "5"; $env:PORT = "8099"
.\.venv\Scripts\serve.exe
# second shell
Push-Location frontend
npx playwright test e2e/capture.spec.ts --project=chromium --project=mobile
Pop-Location
```

| Axis | Values |
| --- | --- |
| Viewport | 1440 × 900 (`chromium`), 390 × 844 (`mobile`, planned in 02) |
| Theme | `data-theme="dark"`, `data-theme="light"` (planned in 02) |
| State | empty · one node · 30-node graph (24 flow + 6 attachment nodes, the maximum the bounds allow) · running (mid-branch, needs the 5 s delay) · errored (`SYNTHETIC_FAILURE=<mode>`, planned in 12) |
| Recording | a `.webm` for the launch sequence and one handoff walk; `video: 'on'` for that spec only |

Reference captures are taken by hand at the same viewport and zoom, with
the browser chrome cropped, and named `<surface>-<state>-<viewport>-<theme>.png`
on both sides so a pair can be matched by filename alone.

## The critic

A **fresh agent** with a separate context: no build history, no access to
the implementer's reasoning. It receives exactly four things:

1. the plan file's *Acceptance criteria* section, and nothing else from the plan;
2. our capture set for the feature;
3. the reference capture set;
4. the rubric rows that apply (below).

Ours and the reference are renamed `A` and `B` by a coin flip recorded in
`rounds/<plan>-<n>.md` before the critic is invoked. The critic is never
told which is ours. Its prompt opens with the gauntlet's sentence, verbatim:

> You are a hostile design director who has shipped a competitor to this
> product. You are looking for reasons to reject. Vague praise is a failure
> of your job.

Personas rotate by round so one blind spot cannot survive four rounds:

| Round | Persona |
| --- | --- |
| 1 | design director |
| 2 | staff frontend engineer |
| 3 | CrewAI power user |
| 4 | first-time user who has never seen a node graph |
| 5+ | repeat from 1 |

### What a defect must look like

A defect is **specific, located, actionable**, or it is rejected and the
critic is re-run:

- rejected: *"feels unpolished"*, *"edges could be clearer"*
- accepted: *"port hit target is 12 px; B's is 24 px; connecting at 50 % zoom took 3 attempts in the recording"*; *"at 390 × 844 the inspector covers the node being edited; B keeps 120 px of canvas visible"*

Each accepted defect carries the dimension, the two scores, the delta, the
file or component it lands in, and the viewport and zoom it was seen at.

### Retirement

A critic that passes an artifact twice running is retired as compromised
and replaced. A first-round pass means the critic was too soft: replace it
and restart the round count.

## Rubric — sixteen dimensions, gate at 8

| # | Dimension | Scored against | Owning plan | What the plan measures |
| --- | --- | --- | --- | --- |
| 1 | New-flow creation — clicks and confusion from landing to first node placed | Flowise | 02, 14 | a new flow seeds an `input` node; template opens pre-wired |
| 2 | Node grammar — agent vs task vs tool vs router at 50 % zoom | Flowise | 03 | shape + colour + icon per kind, pills for attachments |
| 3 | Drag precision — port hit targets, snap radius, success at 50 / 100 / 150 % | Flowise | 02 | 12 px visual / 24 px hit, red/green handles |
| 4 | Inspector ergonomics — clicks to fully configure an agent, error recovery | Flowise | 04 | an eight-pointer-action click budget |
| 5 | Edge legibility — routing, crossings, direction, state | Flowise | 02 | gradient flow edges, class-tinted others, arrowheads |
| 6 | Graph scale — 60 fps pan/zoom at 50 nodes | Flowise | 02 | mean ≤ 16.7 ms, p95 ≤ 20 ms per frame at 48 nodes |
| 7 | Launch sequence fidelity | ChatDev | 11 | the one glow vocabulary plus a negative-delay stagger |
| 8 | Easing character | ChatDev | 11 | the reference's curves and periods, quoted in `docs/chatdev-notes.md` §2 |
| 9 | Message choreography | ChatDev | 11 | the handoff token on `edge_traversal` |
| 10 | Alive vs noisy during a 20-step run | ChatDev | 11 | ≤ 12 live animations, 0 at terminal, idle recede |
| 11 | Compiler correctness — flow JSON → CrewAI → execute → identical result, 20/20 | engineering | 09 | the determinism harness over twenty fixtures |
| 12 | Error handling — six failure modes legible and recoverable | engineering | 12 | `tests/builder/test_failure_modes.py` + the E2E per mode |
| 13 | Cost discipline — no model above the ceiling reachable anywhere | engineering | 05 | `tests/test_model_ceiling.py` |
| 14 | Isolation — user A cannot read, run, or infer user B's flows, runs, credentials | engineering | 01, 15 | `e2e/isolation.spec.ts` with two synthetic identities |
| 15 | Templates — all four run from a cold sign-in with zero configuration | engineering | 14 | the `@launch` cold-sign-in test, then one paid run each |
| 16 | RAMP integrity — every shipped feature has a committed plan file whose criteria are all checked | process | 00 | the plan's `Status` says *Built* only after every criterion is ticked |

Dimensions 11–16 are scored by the Integrator against test output, not by
the visual critic; they still go in the ledger and they still gate.

## The gate

```text
all applicable dimensions ≥ 8
AND no open defect for this feature in DEFECTS.md
AND at least three rounds have run
→ exit: commit, set the plan's Status to Built, close the round file
otherwise → the critic's ranked defect list becomes the build list; goto build
```

"Close enough" is a failure state. A dimension where the reference scores
higher is an open defect regardless of the absolute score.
